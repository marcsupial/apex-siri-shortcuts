# Developing

The shortcuts are generated by Python rather than built by hand in the Shortcuts
app, so they can be reviewed, versioned, and rebuilt consistently.

## Requirements

- A Mac with the Shortcuts app, signed in to iCloud. Shortcuts only imports signed
  files, and signing uses macOS's `shortcuts sign`.
- Python 3.10 or later. There are no third-party packages.

## Build

```sh
python3 tools/build_shortcuts.py            # signed shortcuts in shortcuts/
python3 tools/build_shortcuts.py --no-sign  # readable XML plists in build/, for review
```

Commit the rebuilt files in `shortcuts/`; that's what people download.

## How a shortcut is defined

Each shortcut is a Python function in `tools/build_shortcuts.py` that returns a
`Shortcut`. `feed_shortcut()` is the whole Feed shortcut. The `Shortcut` class wraps
the Shortcuts actions in use:

| Method | Shortcuts action |
|---|---|
| `setting()` | Text, asked for when the shortcut is imported |
| `trimmed()` | Replace Text, removing spaces at either end |
| `request()` | Get Contents of URL |
| `first_group()` | Match Text, then Get Group from Matched Text |
| `dig()` | Get Dictionary Value, one per key |
| `wait()` | Wait |
| `if_()`, `otherwise()`, `end_if()` | If / Otherwise / End If |
| `show()` | Show Result, which Siri speaks |

Adding Feed B is one more entry in `main()`:

```python
builds.append((SHORTCUTS, feed_shortcut("B", args.address)))
```

## Test without touching your tank

`tools/mock_apex.py` is a stand-in Apex. It logs every request and rejects anything
the real Apex wouldn't accept, such as a JSON string where it expects a number, or a
request without a session. When the real Apex behaves differently from the mock, fix
the mock first, so the next test catches it.

```sh
python3 tools/mock_apex.py &                             # http://127.0.0.1:8737
python3 tools/build_shortcuts.py --mock 127.0.0.1:8737   # also builds build/Apex Mock Test.shortcut
open "build/Apex Mock Test.shortcut"                     # click Add Shortcut
shortcuts run "Apex Mock Test"
```

"Apex Mock Test" is the Feed A shortcut pointed at the mock, with the mock's login
built in and padded with spaces: the mock only accepts the exact login, so
"Feed A is running." also proves the trimming works. To check the rejected-login
reply, restart the mock with `--password something-else` and run it again.

Before re-importing a changed shortcut, delete the old copy in Shortcuts. Otherwise
the import is named "Apex Mock Test 2", and `shortcuts run` (or Siri) may run the old one.

## Shortcuts behavior to design around

- **Get Contents of URL doesn't fail on HTTP errors.** A rejected login returns the
  401 page as if it were content, so every step checks its own result. Only a
  connection failure stops the shortcut, with Shortcuts' own error.
- **Don't rely on Shortcuts to carry cookies.** When a request set its own
  `Cookie` header, Shortcuts didn't add the cookie the server had set. The shortcuts
  send the session id explicitly.
- **Read `connect.sid` with a regex.** Get Dictionary Value may treat the dot in
  the key as a nested key path.
- **Typed import answers can be altered.** Autocorrect and smart quotes apply to the
  import questions, which is why the README tells people to paste their login.

## The file format

`CLIENT_VERSION` pins the Shortcuts version the action format was written for. Before
using an action for the first time, check how Apple encodes it in the shortcuts that
ship with macOS (binary plists):

- `/System/Library/PrivateFrameworks/WorkflowKit.framework/Versions/A/Resources/Gallery.bundle/Contents/Resources/*.wflow`
- `/System/Library/PrivateFrameworks/VoiceShortcuts.framework/Versions/A/Resources/*.wflow`

`python3 -c 'import plistlib, sys, pprint; pprint.pprint(plistlib.load(open(sys.argv[1], "rb")))' <file>`
prints one.

## Adding a command

1. **Find the request.** The dashboard's code is at `http://<apex>/main.js` (send
   `Accept-Encoding: gzip`). [apex-ha](https://github.com/itchannel/apex-ha) is a
   good second reference.
2. **Write it up** in [apex-local-api.md](apex-local-api.md).
3. **Teach `tools/mock_apex.py` the endpoint**, strictly: reject what the real Apex
   would reject.
4. **Write the shortcut** as a function, and add it to `main()`.
5. **Test it on the mock**: the success reply and every failure reply.
6. **Test it on a real Apex**, knowing what the command switches on or off.
7. **Rebuild** and commit `shortcuts/`.
